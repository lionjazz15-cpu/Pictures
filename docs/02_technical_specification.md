# 02. ChairMotion Fusion 技術仕様書 v0.2（ドラフト）

> **v0.2 の変更点（2026-10-24）**：採用構成を「**椅子マット（座面＋背もたれ）・床マット・机下 ToF・Webcam**」に決定。顔は既存ツール（iPhone または Webcam）に任せる。ミリ波レーダーは標準構成から外し、将来のオプションとして §3.5 に残す（低コスト化と技適の回避。05 参照）。

## 1. 製品の定義

### 1.1 一行定義
椅子のマット・床のマット・机下のセンサー・既存の Webcam だけで、**着席中の骨盤と下半身を中心とした全身姿勢**を推定し、VMC / Warudo / VRM に送るシステム。

### 1.2 スコープの切り分け（最重要の設計判断）
顔・頭・腕・手は、Warudo や各種フェイストラッカーなど**既存のWebcamトラッキングで十分に実用水準**にある。ChairMotion の価値は**「机に隠れて Webcam から見えない骨盤〜足先」**にある。

| 部位 | 担当 | 方針 |
|---|---|---|
| 顔・表情・視線 | 既存ツール：**iPhone（TrueDepth / ARKit、推奨）または Webcam（MediaPipe）**を Warudo 側で使う | **作らない**。連携のみ（§5.1） |
| 頭・胴・腕・手 | Webcam（MediaPipe 等） | 融合の拘束（肩・胴の向き）として使う。v1 では既存ツールの出力を優先し、ChairMotion の出力は選択式 |
| **骨盤（位置・傾き・回旋）** | **座面＋背もたれの圧力**＋マットIMU＋カメラ | ChairMotion の中核 |
| **太もも・膝** | 圧力（接触）＋机下 ToF ＋脚の長さの拘束 | 中核 |
| **足（床に着いているとき）** | **床マット**（接地・位置・かかと／つま先） | 中核。最も多い状態を実測で押さえる |
| **すね・足首・足先（浮いているとき）** | **机下 ToF** | 中核。観測できない場合は INFERRED と明示する |

## 2. システム全体構成

```
 ┌──────────────┐ USB (Pico #1)         ┌──────────────────────────────────────────┐
 │ 椅子マット    │─────────────────────▶│ ChairMotion Core（PC 常駐）               │
 │ 座面16×16    │ 圧力 60Hz            │  ├ Ingest（センサーごとのドライバー＋時刻付与） │
 │ 背もたれ12×16│ IMU 200Hz（v0.1〜）  │  ├ Preproc（校正・ゼロ点・背景差分）       │
 └──────────────┘                      │  ├ Fusion NN（ONNX Runtime）             │
 ┌──────────────┐ USB (Pico #2)        │  ├ Chair-Rooted IK / 接触・foot lock      │
 │ 床マット      │─────────────────────▶│  ├ Confidence & Source Tagging            │
 │ 16×16        │ 圧力 60Hz            │  └ Output: VMC/OSC・Warudoプラグイン・録画 │
 └──────────────┘                      └──────────────────────────────────────────┘
 ┌──────────────┐ USB (Pico #3)                          │ UDP 39539 (VMC、体)
 │ 机下 ToF ×2  │─────────────────────▶                  ▼
 │ VL53L8CX     │ 8×8 15Hz / 4×4 60Hz      Warudo ◀── iPhone（顔、任意）／Webcam（顔）
 └──────────────┘                            │
 ┌──────────────┐ UVC                        ▼
 │ 既存 Webcam  │─────────────────────▶  配信ソフト
 └──────────────┘
```

すべて「置くだけ」で、身体への装着はゼロ。電波を出す部品がないため技適は不要（§9）。

座標系は3つある：**椅子座標系 C**（座面マットの中心が原点、x=右、y=前、z=上）、**机座標系 D**（床マットの角が原点。机下 ToF も机に固定なので D 系に属する）、**カメラ座標系 K**。
**椅子は回転し、キャスターで移動する**ため、C と D の変換 `T_DC(t)` は**時々刻々と変わる**。これを推定し続けることが、机下センサー方式の隠れた最難関（§6.3）。

## 3. 机下センサー（DeskSensor）

### 3.0 採用構成（v0.2）：ToF を標準、レーダーはオプション

| 項目 | 標準構成 |
|---|---|
| センサー | **ST VL53L8CX（マルチゾーン ToF）×2**。机の天板裏の左右に1個ずつ、内向き・下向きに傾けて、すね〜足先を斜めから見る |
| 分解能 | 8×8 ゾーン（FoV 約 45°×45°、1ゾーン約 5.6°）＝ 距離 0.5m で**横方向に約 5cm**。各ゾーンで複数の対象（例：膝と床）を分離して返せる |
| レート | 8×8 で約 15Hz、4×4 で約 60Hz。**近い側の脚を見る1台は 4×4・60Hz**、全体を見る1台は 8×8・15Hz などの使い分けを Phase 2 で比較 |
| 接続 | I2C（2台は LPn ピンでアドレスを変更）→ 小型 RP2040 ボード → USB。**椅子と床の Pico とは別の USB デバイス** |
| 背景 | 無人時の距離マップを背景として記録し、差分で脚だけを取り出す（机の脚・引き出し・椅子の脚を除去） |
| 担当 | **浮いている足**（脚組み・膝上げ・足を前に伸ばす）と膝。床に着いている足は床マットが主担当 |
| 法規 | 電波を出さない。レーザーの安全クラスはデータシートで確認（VL53L8CX はクラス1とされる） |

以下 §3.1〜3.3 と §3.5 は、レーダーを将来のオプション（Pro 構成）として検討するための参考情報として残す。

### 3.1 レーダーチップの比較（オプション）

| 候補 | 送受信 | 帯域 | 特徴 | 位置づけ |
|---|---|---|---|---|
| **TI IWR6843AOP**（EVM: IWR6843AOPEVM） | 3TX/4RX（仮想12ch）、アンテナはパッケージ内蔵 | 60〜64GHz（4GHz → 距離分解能 3.75cm） | 研究実績・SDK・デモ（3D People Tracking 等）が最も豊富。MM-Fi など公開データでも採用。FoV は 120°×120° 程度とする資料あり（資料ごとに値が違うので要実測） | **Phase 2 の基準機** |
| **TI IWRL6844**（EVM: IWRL6844EVM / xWRL6844EVM） | **4TX/4RX（仮想16ch）** | 57〜64GHz | C66x DSP＋HWA、平均 500mW 未満。4本目の送信で角度分解能が向上。SDK は MMWAVE-L-SDK-6（2025-12 リリース）。EVM はアンテナが PCB 上（AOP ではない） | **製品版の第一候補**（角度分解能が最重要なため） |
| TI IWRL6432 | 少チャネル・低消費電力 | 57〜64GHz | 在席・ジェスチャー向け | 角度分解能が不足する見込み。参考のみ |
| Infineon BGT60TR13C 系 / 技適済みモジュール（NJR4652 系等） | 1TX/3RX 程度 | 60GHz | 技適を取得済みの小型モジュールがある | 角度分解能が低い。**状態検出の補助のみ** |
| Acconeer A121 系 | パルス式・単チャネル | 60GHz | 距離精度は高いが角度は取れない | 足先までの距離計として補助に使える可能性 |
| カスケード型のイメージングレーダー | 多数 | 77GHz 等 | 高密度だが高価・大型 | 対象外 |

> **最重要の物理的制約：角度分解能**
> 仮想アンテナ数 N の一様アレイの角度分解能は、おおよそ Δθ ≈ 2/N [rad]。IWR6843AOP は各軸に実効4素子程度なので **Δθ ≈ 29°** となり、距離 0.4m では**横方向の分解能 ≈ 20cm**。
> 左右の膝の間隔は 15〜30cm なので、**角度だけでは両脚を安定して分離できない可能性が高い**。一方、距離分解能は 3.75cm と細かい。
> → 設計方針：**両脚が「異なる距離」に来るように設置する**（斜めの配置、§3.3）＋ドップラー＋時系列の追跡で分離する。Capon / MUSIC などの超解像は補助的に使う（近距離のマルチパスで破綻しうる）。

### 3.2 レーダー信号処理の要件（オプション）

| ID | 要件 | 理由 |
|---|---|---|
| RAD-01 | **静止クラッタ除去を無効化するか、空の状態で取った背景との差分に置き換える** | TI のデモでよくある「静止物の除去」では、**じっと座っている脚が消える**。椅子・机・床の静止反射は、無人時に取った背景（レンジ・角度ヒートマップ）を差し引いて抑える |
| RAD-02 | 最小距離を 0.15m 程度に設定し、それより手前は捨てる。距離バイアスと位相のキャリブレーションを実施 | 近距離での送受信の回り込み・近傍界の影響 |
| RAD-03 | フレームレート 30〜50Hz、チャープは TDM-MIMO | ドップラー分解能は足を揺する速度（0.05〜0.5m/s）を分けられる程度に |
| RAD-04 | 出力は2系統：(a) CFAR 点群（x,y,z,v,SNR）、(b) **距離×方位×仰角（または距離×角度×ドップラー）のヒートマップ** | 近距離の静止した脚は点群だと消えやすい。**本命は (b)**。研究段階は DCA1000EVM で生ADCを取り、どのヒートマップ表現が良いかを決めてから、それを実機DSPで出力できるか検証する |
| RAD-05 | 2台構成にする場合はフレームを同期させ時分割（ハードウェアトリガ）、または周波数を分ける（例：60–62 / 62–64GHz、距離分解能は 7.5cm に落ちる） | FMCW レーダー同士の干渉 |
| RAD-06 | 金属天板・引き出し・幕板のマルチパスを考慮し、**設置ごとに背景を学習**する | 机ごとの差が大きい |

### 3.3 設置ジオメトリ（Phase 2 で比較する候補。ToF にも同じ位置の考え方を使う）

机の天板高さを 70〜72cm、膝の高さ（着席時）を 45〜55cm、天板裏から膝上までを 15〜25cm と想定する。

| 配置 | 内容 | 期待 | 懸念 |
|---|---|---|---|
| **P1：奥・中央・下向き** | 天板裏の、手前の縁から 30〜40cm 奥の中央。ピッチは下向き 30〜45°で着席者に向ける | 膝まで 0.35〜0.5m、足先まで 0.6〜0.8m で、最小距離の問題を回避できる | 左右の脚の分離（角度分解能） |
| **P2：奥・左右オフセット・斜め** | 中央から左右に 25〜35cm ずらし、ヨーで 20〜30° 内向き | **両脚の距離差が大きく**、分離しやすい | 遠い側の脚が近い側の脚に遮られる（特に脚組み時） |
| P3：手前の縁の直下 | 手前の縁の裏、真下向き | 設置が簡単 | 膝まで 0.15〜0.25m と近すぎ、FoV からはみ出す |
| P4：モニター上（比較用） | — | 上半身と同時に見られる | 机に遮られて脚が見えない |
| P5：椅子の後方（比較用） | — | 骨盤と背中 | 背もたれに遮られる。製品にはしない |
| **P6：P2 を左右2台** | 左右の奥に各1台 | 脚組み時の遮蔽を補完 | 原価・干渉・技適が2台分 |

**推奨する順序**：P1 → P2 → P6（必要な場合のみ）。2台目は、**P2 で左右の分離率が 95% 未満、または脚組み時の足首の追跡不能率が 30% を超える場合**に検討する。

固定具：天板裏用のクリップ、または 3M VHB テープ＋ボールジョイント。**ピッチ・ヨーの目盛り付き**にする（キャリブレーションの初期値に使う）。

### 3.4 机下の光学センサーの候補

v0.2 で ToF を標準にした理由：レーダー固有のリスク（角度分解能・静止物・マルチパス・技適）に対し、机下は暗く、脚しか映らないためプライバシー上も光学式で問題ない。

| 候補 | 特徴 | 役割 |
|---|---|---|
| **ST VL53L8CX**（マルチゾーン ToF、8×8ゾーン） | 安価（ブレイクアウト基板で数千円）、無線ではないので技適不要、FoV は対角約65° | 低コストの補助：足先・すねの距離マップ。8×8 は 15Hz、4×4 は 60Hz 程度 |
| 近距離のステレオ深度（RealSense D405 等） | 近距離に強い高密度の深度 | **開発時のリファレンス**、または上位モデルの選択肢 |
| IR カメラ＋IR LED（グローバルシャッター） | 安価。2D キーポイントを取得 | 机下の 2D 補助。真上からの視点は学習済みモデルに不利 |

Phase 2 の判定（§10）は **ToF で先に行い**、No-Go の場合のみレーダーを追加して比較する。

### 3.5 レーダーを再検討する条件
- ToF で浮いた足首の追跡不能率が 30% を超える（暗い色の服・遮蔽など）
- 速い動き（足の揺すり）で ToF のレートが足りない
上記の場合に限り、§3.1〜3.3 の構成（技適取得済みモジュールを前提）で Pro 構成として再評価する。

## 4. 座面マット（SeatPad）

### 4.1 構成

| 項目 | MVP（v0） | 製品候補（v1） |
|---|---|---|
| 座面 | 16×16、ピッチ約 2.8cm（45cm角） | **32×32、ピッチ約 1.4cm**（坐骨の間隔 10〜13cm を 7〜9 セルで捉える） |
| 背もたれ | なし | **16×24 の帯状**（腰〜肩甲骨）。ChairPose も背もたれを含めている。寄りかかり・ひねりの観測に必須 |
| IMU | なし | **座面の基板に1個＋背もたれに1個**（6軸、例：BMI270 / ICM-42688 クラス）。椅子のヨー回転・リクライニング角・揺れを測る |
| MCU | ESP32-S3 | ESP32-S3、または外部 ADC 付きの STM32 / RP2350 |
| 接続 | USB-C（CDC） | USB-C（バルク転送）＋ USB の SOF を時刻基準に（§6.1） |
| サンプリング | 30〜60Hz | **60Hz 固定**（座面1024＋背もたれ384 = 1,408セル → 約 85k サンプル/秒） |

> マットの IMU は**身体ではなく椅子に付く**ので「装着ゼロ」に反しない。椅子の回転を直接測れることは、§6.3 の座標系問題に対する最も安価で確実な解決策である。

### 4.2 センサー材料（3種を比較）

| 材料 | 長所 | 短所 | 用途 |
|---|---|---|---|
| Velostat / Linqstat（カーボン入りフィルム） | 安価・入手しやすい・加工しやすい | **ヒステリシス・クリープ・温度ドリフト・ロット差**が大きい。折り曲げで劣化 | MVP |
| ピエゾ抵抗布（EeonTex 等） | 柔軟・通気性・座り心地 | 価格が高め、湿度の影響 | v1 の候補 |
| 印刷 FSR（PET 上の銀電極＋カーボンインク） | **量産時に低コスト・特性が均一** | 硬い・折り曲げ耐久の確認が必要 | v1 の候補（TPU ラミネートで保護） |

電極：導電布テープ、または刺繍した導電糸（布マット）。v1 は**片面ずつ電極を印刷したフィルム2枚で感圧層を挟む**構造にする。表面は TPU ラミネート＋布カバー（洗濯できるカバーを外付け）。

### 4.3 読み出し回路（クロストーク対策）

- **ゼロ電位法（Zero-Potential Method）を推奨**：選択した行を Vref で駆動し、**非選択の行はすべて GND**。各列はオペアンプのトランスインピーダンス（仮想接地）で読む。すべての列が 0V に保たれるので、並列の回り込み経路に電流が流れず、ゴースト圧力が大幅に減る。
  - 32列 → クワッドオペアンプ×8 → 8ch のアナログマルチプレクサ×4 → ADC。行の駆動はシフトレジスタ＋アナログスイッチ（または MCU の GPIO を直接）。
- MVP（gmntu/psa 型：CD74HC4067 で行と列をマルチプレクスして分圧で読む）でも動くが、クロストークは**ソフトウェアで補正する前提**になる。
- ADC：ESP32-S3 内蔵の SAR は非線形性とノイズがあるため、v1 は外部 ADC（12〜16bit、≧200kSPS、例：ADS7953 クラス）を推奨。
- 1セルごとのセトリング時間を確保する（感圧層の RC）。1,408セル×60Hz で、1セルあたり約 11µs の予算。

### 4.4 校正とドリフト補正

| 手順 | タイミング | 内容 |
|---|---|---|
| 工場校正 | 出荷時 | 空気袋（ブラダー）で**均一圧を数段階**かけ、セルごとの R–P 曲線（べき乗則 `G = a·P^b`）を当てはめて係数を保存 |
| ゼロ点の更新 | 離席を検出するたび | 無荷重のベースラインを更新（温度ドリフトを吸収） |
| クリープ補正 | 常時 | 1次遅れモデル＋荷重の総和の変化に対する補償。**学習モデルには絶対値ではなく、正規化圧力と時間差分も入力する** |
| 体重の正規化 | 着席ごと | 合計荷重で正規化（体型差・ロット差の吸収） |
| 不良セルの検出 | 常時 | 長時間 0 または飽和のままのセルをマスクする（学習時もランダムにマスクして頑健化） |
| 温度 | 常時 | 基板の温度センサーの値を特徴量に加える |

### 4.5 床マット（FloorPad）

| 項目 | v0 |
|---|---|
| 有効エリア | 幅 60 × 奥行き 48cm、16×16（ピッチ 3.75 × 3.0cm） |
| 回路 | 椅子マットと共通（行ドライバー2個分）。**別の Pico・別の USB** |
| 表面 | EVA フォーム／ゴムマット 3〜5mm（キャスター・靴対策、点荷重の分散） |
| 出力 | 左右の足の接地状態（full / toe / heel / partial / lifted）、圧力中心の位置（D 系、cm）、荷重 |
| 製作 | [07 床マット製作ガイド](07_floorpad_v0_build_guide.md) |

床マットの効果：
1. **最も多い状態（足が床に着いている）を実測**できる。
2. 接地中は足の位置を固定（foot lock）でき、アバターの足が滑る破綻を防げる。
3. 両足（D 系）と骨盤（C 系）が脚の長さでつながるので、**椅子の位置・回転の推定**（§6.3）の手がかりになる。

## 6. 時刻同期・キャリブレーション

### 6.1 時刻同期

| ID | 方式 |
|---|---|
| SYNC-01 | PC のモノトニック時計を基準にし、受信時刻にドライバー層でタイムスタンプを付ける |
| SYNC-02 | SeatPad：MCU 側でサンプル時刻を付け、PC との往復 ping（1Hz）で**オフセットとドリフトを線形推定**（簡易版 NTP） |
| SYNC-03 | 床マット・机下 ToF：SYNC-02 と同じ方式（各 Pico に PING/PONG。実装済み：`tools/pressure_pad`） |
| SYNC-04 | カメラ：キャプチャAPIのタイムスタンプ（Media Foundation / DirectShow）。露光遅延のオフセットは機種ごとに推定 |
| SYNC-05 | **イベントによる自動合わせ込み**：キャリブレーション中に「足踏み1回＋手を叩く」を行い、座面・床マットの圧力の急変・ToF の距離の急変・カメラの手首の加速度ピークの相互相関から、センサー間の残りのオフセットを推定 |
| SYNC-06 | 研究時の記録は Lab Streaming Layer（LSL）で統一。製品の実行環境では SYNC-01〜05 を自前で実装する |

融合の時間軸は **16.7ms（60Hz）のグリッド**。各センサーの最新サンプルを、その時刻差（Δt）と一緒にモデルに入力する（補間はモデルが学習する）。

### 6.2 初期キャリブレーション（30秒・案内付き）

1. **無人の背景**：ToF（とレーダーを使う場合はレーダー）で、椅子が普段の位置にあり人がいない状態の背景を5秒取得。同時に椅子マット・床マットのゼロ点も取得。
2. **基本姿勢**：普通に座り、正面を向いて5秒（体重・坐骨の位置・椅子のヨーの基準・カメラでの胴の向き）。
3. **脚の動作**：右膝を上げる → 左膝を上げる → 足を前に伸ばす → 戻す（各2秒）。座面の圧力の変化（太ももが離れる）・床マットの接地の変化・ToF の距離変化の対応から `T_DC` を初期化し、左右のラベルを決める。
4. **同期イベント**：足踏み1回＋手を叩く（SYNC-05）。足踏みは床マット・座面・ToF に同時に現れるので、3つのデバイスの時刻合わせに使える。

### 6.3 オンライン補正：椅子の回転・移動への追従（最重要）

`T_DC(t)` は、椅子のヨー回転（±90°以上）・前後左右の移動（±30cm）・リクライニングで常に変わる。

推定はファクターグラフ（または EKF）で行い、状態量は `[x, y, yaw, recline]`：

| 入力 | 観測する量 |
|---|---|
| マットIMU（ジャイロ z 軸） | ヨー角速度（高レート・ドリフトあり） |
| 背もたれIMU | リクライニング角 |
| Webcam の肩のヨー | ヨーの絶対値の補正（胴のひねりと椅子の回転を分けるため、骨盤の回旋は圧力分布から推定） |
| **床マットの両足の位置（D 系）** | 骨盤（C 系）から脚の長さ以内にある → 椅子の位置・ヨーを拘束 |
| ToF の静的な反射 | 椅子の脚・ガスシリンダーなど、椅子の構造物の位置（見える場合） |
| 圧力の合計荷重の変化 | 移動中か静止中かの判定（ZUPT 的に利用） |
| 運動学の整合性 | 骨盤（C 系）と足先（D 系）の距離は脚の長さ以下 |

## 7. センサーフュージョン AI

### 7.1 設計思想
1. **センサー表現・身体の事前分布・対応付けを分離**する（Wave2Body の考え方）。ペアデータ（全センサー＋正解）は高価なので、対応付けの部分だけをペアデータで学習する。
2. **出力は分布**（平均＋分散）にし、分散を信頼度・ソースタグの根拠にする。
3. **因果的**（未来のフレームを使わない）。遅延は REQ-03 で制約する。

### 7.2 モデル構成

```
 Pressure seq (T×[32×32 + 16×24], 正規化+差分)  ─▶ PressureEnc (2D-CNN + 時間Conv)        ─┐
 IMU (chair yaw/recline)                        ─▶ 小型MLP                               ─┤
 Floor pressure seq (T×16×16) + 足の検出結果    ─▶ FloorEnc (2D-CNN + 時間Conv)           ─┤ modality tokens
 ToF ×2 (8×8 or 4×4 depth, multi-target)        ─▶ ToFEnc（小型CNN、背景差分済み）        ─┤ (+Δt埋め込み,
 Radar (オプション、Pro 構成のみ)                 ─▶ RadarEnc                              ─┤
 Vision landmarks (upper body, conf)            ─▶ MLP                                   ─┤   +センサー姿勢埋め込み)
 前フレームの姿勢 / 骨長 / 椅子・机ジオメトリ    ─▶ 埋め込み                               ─┘
                                                         │
                                ┌────────────────────────▼─────────────────────────┐
                                │ Fusion Transformer（関節クエリ×モダリティトークン、│
                                │ 因果的な時間アテンション 1秒窓、modality dropout）  │
                                └────────────────────────┬─────────────────────────┘
                                                         ▼
                        Body-token decoder（自社データで学習した身体の事前分布）
                                                         ▼
       出力: 関節の位置と回転（VRM Humanoid のボーン）、関節ごとの分散 σ²、接触の確率、状態クラス
                                                         ▼
                       Chair-Rooted IK + 接触・関節可動域・骨長の拘束（§7.5）
```

| 部品 | 規模（目安） | 学習データ |
|---|---|---|
| PressureEnc | 約 0.5M パラメータ | ペアデータ＋物理シミュレーションの合成データ（§7.4） |
| FloorEnc | 約 0.3M | ペアデータ。足の検出（ルールベース、07 §6）を補助入力に |
| ToFEnc | 約 0.3M | **ラベルなし ToF データで自己教師あり事前学習**（マスク再構成）→ ペアデータで微調整 |
| 身体トークナイザ（VQ） | 約 1M | **姿勢データのみ**（自社の着席モーキャプ＋商用可能なモーションDB、Anny / MHR のスケルトンに変換） |
| Fusion Transformer | 2〜5M | ペアデータ |
| 合計の推論コスト | CPU 1コアで 1フレーム 5ms 未満を目標 | ONNX Runtime（CPU / DirectML）、INT8 量子化を検証 |

### 7.3 損失関数
- 関節位置の L1 ＋ Gaussian NLL（分散の学習）
- 骨長の一貫性、関節可動域の違反ペナルティ
- **接触の整合性**：圧力のある領域 ⇔ 太もも・臀部の表面が座面上、足が床にある ⇔ 足先の z ≈ 0 かつ速度 ≈ 0
- 時間方向の平滑性（加速度のノルム）。ただし**本物の速い動き（足の揺すり）を潰さない**よう、床マットや ToF に速い変化が出ているフレームでは重みを下げる
- 状態分類のクロスエントロピー（補助タスク）

### 7.4 データ拡張と合成データ
- **物理シミュレーションによる圧力の合成**（ChairPose の考え方を独自に再実装）：Anny で体型を生成 → 着席姿勢 → 柔らかい座面との接触を解いて圧力マップを生成。実データとの差は、ノイズ・クロストーク・不良セル・ゲイン差の付与で埋める。
- 床マット：座面と同じ方法で、足の接触から圧力を合成。
- ToF：人体メッシュに対するレイキャストで距離マップを合成（マルチパスがないため、レーダーより現実との差が小さい見込み）。
- センサー外部パラメータのジッター（±5°、±3cm）、時刻オフセットのジッター（±30ms）、**モダリティドロップアウト**（各 p=0.2〜0.3）、椅子のヨーのランダム化。

### 7.5 Chair-Rooted IK と物理・接触の拘束
1. **骨盤のアンカー**：圧力から求めた左右の坐骨の位置 → 骨盤の中心・左右の傾き（obliquity）・回旋。背もたれの圧力と IMU → 前後傾。
2. **胴**：骨盤から上は、カメラの肩の姿勢を目標に、FABRIK または解析的 IK で解く。
3. **脚**：骨盤 → 膝 → 足首の 2-bone IK。目標値は融合NNの膝・足首の出力。膝の向き（ポールベクトル）は太ももの接触パターンから決める。
4. **接地のロック**：足が床に接している確率が高く、速度が低い間は、足の位置を D 系で固定（foot lock）し、足が滑って見えるのを防ぐ。
5. **自己接触**：脚組み時は、上の脚の太ももが下の脚の膝上に乗るように、カプセル同士の衝突を解く。
6. **フィルタ**：信頼度に応じてパラメータを変える One Euro Filter（σ が大きいほど強く平滑化）。

### 7.6 Confidence-Aware Fusion とソースタグ

ボーンごとに、出力の分散 σ と観測の有無から、次の3段階のタグを付ける：

| タグ | 条件（例） | 挙動 |
|---|---|---|
| **MEASURED** | 対応するセンサーに十分な観測がある（例：床マットで接地している、ToF の該当ゾーンで背景と異なる有効な距離が得られている）かつ σ < 4cm | そのまま出力 |
| **INFERRED** | 観測が弱い・遮蔽されている。圧力と過去の状態から推定 | 時間とともに**事前分布の自然な姿勢へ減衰**。動きの振幅を抑え、架空の動きを作らない |
| **HELD** | 観測が途絶して 0.5 秒以上 | 最後の MEASURED の姿勢を保持し、ゆっくり中立姿勢へ戻す |

タグは VMC の拡張メッセージ（`/ChairMotion/Bone/Source <name> <tag> <sigma>`）と UI の色分けで公開する。**製品説明の精度表記は MEASURED のフレームのみで算出**し、INFERRED を含む値と分けて記載する。

## 8. ソフトウェア仕様

### 8.1 構成
| 層 | MVP | v1 |
|---|---|---|
| センサードライバー | Python（pyserial, pyusb, OpenCV） | Rust または C++ の常駐サービス |

| 出力 | VMC（OSC/UDP） | VMC＋Warudo プラグイン（C#）＋録画（BVH / FBX / VRMA） |

### 8.2 出力プロトコル
- **VMC Protocol**：`/VMC/Ext/Root/Pos`、`/VMC/Ext/Bone/Pos {HumanBodyBones名} px py pz qx qy qz qw`、送信先 UDP 39539（Warudo の受信側の既定ポート）、60Hz。
- **部分送信モード**：Hips・脚（UpperLeg / LowerLeg / Foot / Toes）・Spine だけを送り、上半身は他のトラッカーに任せる。
- **Warudo プラグイン**：WarudoPluginExamples の VMC 例と同じく `PoseTrackingTemplate` として登録し、ソースタグ・信頼度をブループリントのノードに公開する。
- VRM 0.x / 1.0 の Humanoid ボーン名に準拠。T ポーズの差は受信側でリターゲットする。

### 8.3 記録フォーマット（研究・データセット用）
- コンテナ：センサーごとに分けた MCAP、または HDF5。全サンプルにモノトニック時刻・センサーID・外部パラメータのバージョンを付ける。
- メタデータ：被験者ID（仮名化）、身長・体重・股下、椅子ID（3Dスキャン）、机ID（高さ・材質・幕板の有無）、衣服、センサー配置（P1〜P6）、ファームウェアのバージョン。

### 8.4 遅延の計測方法
LED を点灯させると同時に、圧力マットを叩く治具（ソレノイド）を動かし、その様子と画面のアバターを 240fps のカメラで撮影。「LED が点いてからアバターが動くまで」を、センサー別・全体で計測する。

## 10. フェーズ別の Go/No-Go 判定基準

| フェーズ | 判定項目 | Go の条件 | No-Go の場合 |
|---|---|---|---|
| Phase 1（座面） | 着席・離席・脚組み左右・前傾・寄りかかりの分類（被験者3名、本人以外で評価） | F1 > 0.85 | 32×32 化・背もたれの追加・材料の変更 |
| Phase 1 | 30分座り続けた後のドリフト | 合計荷重の変化 < 5%、ゼロ点のずれ < 2% FS | 材料の変更（印刷 FSR）／クリープ補正の強化 |
| Phase 1（床） | 左右の接地判定（被験者3名） | F1 > 0.95（REQ-13） | しきい値・Rf・表面材の見直し |

| **Phase 2（机下 ToF）** | 膝の検出率（静止中を含む） | > 95% のフレーム | 背景差分の見直し → 設置角度 → レーダーの追加検討（§3.5） |
| **Phase 2** | 左右の脚の分離（ラベル付けの正答率） | > 95% | ToF の向き・台数の見直し |
| **Phase 2** | 単純な手法（クラスタリング＋ルール）による膝・足首の位置誤差（Vive トラッカーとの比較） | 膝 < 6cm、足首 < 10cm | 学習で改善できる余地を評価。足首が観測できない場合は「足首は INFERRED」と製品の仕様を下方修正 |
| Phase 2 | 浮いた足首の追跡不能率 | < 30% | レーダーを追加して比較（§3.5） |
| Phase 5 | 「椅子マット＋床マット＋Webcam」に ToF を加えて改善するか | 浮いた足首の MPJPE が 30% 以上改善し、かつ有意 | 机下 ToF を製品から外し、「椅子＋床マット＋カメラ」の安価版にする |
| Phase 6 | 遅延・負荷 | REQ-03・REQ-12 を満たす | モデルの縮小・量子化 |
